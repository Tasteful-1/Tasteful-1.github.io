# AIMT 가이드 작성 기준

이 문서는 AIMT 사용자 가이드를 작성하거나 재생성할 때 적용하는 단일 기준입니다.
대상 독자는 초중급 사용자이며, 문서는 사용자가 화면에서 보고 선택하고 입력하고 실행하고 결과를 확인할 수 있는 정보만 설명합니다.
내부 구현 방식, 함수명, 개발용 검증 표현, 로컬 작업 경로는 설명하지 않습니다.

## AIMT 적용 원칙

1. 문서는 사용자의 작업 성공을 기준으로 구성합니다.
2. 첫 화면에서 사용자가 다음 행동을 정할 수 있어야 합니다.
3. 설명은 기능 중심보다 작업 목적 중심으로 씁니다.
4. 절차는 사용자가 실제로 누르거나 확인하는 순서로 씁니다.
5. 결과 확인 기준을 절차와 분리해 명확히 둡니다.
6. 고급 설정과 내부 참고 문서는 설정 화면이나 관련 기능 문서에서 접근하게 합니다.
7. 주의문은 책임 회피가 아니라 사용자가 취할 행동을 먼저 말합니다.
8. API key, 모델명, 정규식, 명령 코드처럼 사용자가 직접 판단해야 하는 기술 정보는 유지합니다.
9. 내부 구현, 개발자 관점 설명, 로컬 작업 경로, 기준 프로젝트명은 가이드 본문과 검색 인덱스에 쓰지 않습니다.
10. 기준 프로젝트는 UI 이름, 메뉴명, 설정명, 실제 동작 표현을 확인하는 읽기 전용 참조로만 사용합니다.

## 페이지 유형

생성 스크립트는 다음 세 값을 기준으로 페이지를 렌더링합니다.

- `PAGE_TYPE_TEMPLATES`: 페이지 유형별 섹션 흐름입니다.
- `PAGE_METADATA`: 중요 문서의 요약, 사용 시점, 준비 사항, 절차, 확인 기준입니다.
- `PAGE_TYPE_BY_PATH`: 경로만으로 유형을 확정해야 하는 문서의 매핑입니다.

중요 문서도 별도 전용 함수로 처리하지 않습니다.
API KEY 설정, AI-MODEL, 번역 설정, 빠른번역, FAQ 같은 문서는 `PAGE_METADATA`와 공통 템플릿으로 작성합니다.

## 새 Template Rules

### 홈

목적: 처음 온 사용자가 AIMT의 역할, 시작 조건, 전체 흐름, 다음 문서를 판단하게 합니다.

섹션 순서:

1. 이 설명서에서 할 수 있는 일
2. 처음 시작할 때 정할 것
3. 기본 번역 흐름
4. 엔진별 시작 경로
5. 자주 찾는 작업
6. 작업 전 주의사항

### 허브

목적: 하위 문서로 빠르게 이동시키고, 같은 내용을 반복하지 않습니다.

섹션 순서:

1. 이 영역에서 확인할 수 있는 것
2. 바로 이동
3. 처음이라면

### 기능

목적: 기능의 역할, 필요한 상황, 실행 방법, 완료 후 확인 기준을 알려 줍니다.

섹션 순서:

1. 무엇을 할 수 있나요?
2. 언제 필요한가요?
3. 시작 전에 확인할 것
4. 따라 하기
5. 화면과 항목
6. 완료 후 확인
7. 주의/중요/권장
8. 자주 헷갈리는 점

### 작업 흐름

목적: 프로젝트 지정, 추출, 번역, 적용처럼 순서가 중요한 단계의 완료 기준을 분명히 합니다.

`기본 작업 흐름`은 링크만 모아 둔 허브로 만들지 않습니다. 처음 프로젝트를 여는 단계부터 게임에서 결과를 확인하는 단계까지 한 번에 따라갈 수 있게 씁니다. 세부 설정은 반복해서 설명하지 않고 해당 단계의 문서로 연결합니다.

섹션 순서:

1. 이 단계의 목적
2. 언제 진행하나요?
3. 시작 전에 확인할 것
4. 진행 순서
5. 화면과 항목
6. 완료 기준

### 시작 문서의 역할 구분

- 홈은 AIMT가 무엇인지 설명하고, 기본 작업 흐름이나 엔진별 가이드로 이동하게 합니다.
- 기본 작업 흐름은 프로젝트 지정, 추출, 번역, 적용, 게임 실행 확인을 실제 순서대로 안내합니다.
- 엔진별 가이드는 공통 순서를 되풀이하기보다 해당 엔진에서 달라지는 준비와 적용 방법을 설명합니다.
- 스크린샷은 별도 갤러리에 모으지 않고 필요한 단계 가까이에 둡니다.

### 엔진

목적: 사용자가 지금 다루는 게임 형식에 맞는 준비 사항과 제한을 확인하게 합니다.

섹션 순서:

1. 이 엔진에서 확인할 것
2. 시작 전에 확인할 것
3. 진행 순서
4. 화면과 항목
5. 완료 후 확인
6. 주의/중요/권장

### 문제 해결

목적: 설정을 바꾸기 전에 실패 단계와 확인 순서를 좁히게 합니다.

섹션 순서:

1. 먼저 확인할 것
2. 문제 해결 순서
3. 질문과 답변
4. 그래도 해결되지 않을 때

### 고급 참고

목적: AIMT 사용 중 함께 확인하기 좋은 외부 사이트, API 제공자 문서, 출처 링크를 한곳에 모읍니다.

섹션 순서:

1. 이 참고 문서의 범위
2. 변경 전 확인할 중요 사항
3. 참고 내용

### 명령 코드 참고

목적: RPG Maker 이벤트 명령을 확인하거나 번역 결과의 명령 구조를 점검할 때 필요한 정보만 둡니다.

섹션 순서:

1. 명령 코드 참고 범위
2. 변경 전 확인할 중요 사항
3. 명령 코드 참고

## 문체 규칙

- 짧고 직접적인 한국어를 사용합니다.
- `확인합니다`, `선택합니다`, `저장합니다`, `실행합니다`처럼 행동 동사를 씁니다.
- 절차는 번호 목록으로, 확인 조건과 선택지는 글머리표로 씁니다.
- 한 절차 단계에는 하나의 주요 행동만 둡니다.
- 사용자가 화면에서 찾아야 하는 UI 라벨은 실제 표기를 유지합니다.
- `현재 코드 기준`, `내부적으로`, `raw state`, `스레드`, 내부 함수명, 개발자 검증 표현은 제거하거나 사용자 행동 중심 표현으로 바꿉니다.

## 주의문 규칙

- `주의`: 작업 손실, API 키 노출, 결과 파손, 잘못된 적용 위험이 있을 때 사용합니다.
- `중요`: 다음 단계로 가기 전에 반드시 확인해야 할 조건을 말할 때 사용합니다.
- `권장`: 더 안전하거나 효율적인 선택지를 안내할 때 사용합니다.

좋은 예: `주의: API 키는 개인 인증 정보입니다. 공개 문서나 스크린샷에 노출하지 마세요.`

피할 예: `주의: 이 문제에 대한 책임은 사용자에게 있습니다.`

## 기술 정보 처리 규칙

일반 문서에 유지할 수 있는 정보:

- API key
- 모델 이름
- 언어 방향
- 사용자가 선택하는 파일 경로
- 게임 엔진별 제한
- 사용자가 입력하는 정규식
- 사용자가 확인하는 RPG Maker 명령 코드
- 외부 서비스 할당량 또는 정책처럼 사용자의 선택에 영향을 주는 정보

설정 화면이나 관련 기능 문서에서 접근하게 할 정보:

- 정규식 세부 설명
- RPG Maker 명령 코드 참고
- MVMZ 고급 추출 옵션
- 파일 형식과 인코딩 참고
- 로컬 모델 서버 참고

`참고 자료` 목차에는 다음 내용만 둡니다.

- 외부 유틸리티
- API 제공자별 공식 문서와 API 키 발급 링크
- 모델/제공자 호환성 확인에 필요한 외부 문서
- 이미지 출처나 외부 자료 출처 링크

## 생성 스크립트 구현 메모

`scripts/renew_user_manual.py`의 `DUPLICATE_TEMPLATE_SECTION_TITLES`는 공식 작성 기준이 아닙니다.
이 목록은 기존 원문에서 새 템플릿 섹션과 겹치는 제목을 제거하기 위한 정리용 목록입니다.

작성 기준을 바꿀 때는 다음 순서로 반영합니다.

1. 이 문서에서 페이지 유형과 섹션 흐름을 먼저 수정합니다.
2. `PAGE_TYPE_TEMPLATES`에 같은 흐름을 반영합니다.
3. 중요 문서는 `PAGE_METADATA`를 수정합니다.
4. 필요할 때만 `PAGE_TYPE_BY_PATH`를 추가합니다.
5. 가이드를 재생성한 뒤 본문, 목차, 검색 인덱스에 금지 표현이 남지 않았는지 확인합니다.
